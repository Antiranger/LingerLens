# 同一说话人换语调被判成两个人 —— 不换模型的解决方案

> 前置说明：本文假设生产路径是 `companion/providers/diar_sherpa.py`（sherpa-onnx CAM++）
> + `companion/speaker_attribution.py`（`SpeakerGallery`）。如果另一条链路用的是
> pyannote embedding，本文所有改动同样适用 —— 它们全部在 embedding **外面**，
> 只依赖「给我一段 PCM，还我一个向量」这个契约。

---

## 0. 先定性：这不是模型不行，是打分和判决方式不行

同一个人换语调，embedding 一定会动。这是所有 speaker embedding 模型的固有性质：
它编码的是「声道特征 + 说话方式」，语调、情绪、音量、离麦距离都会推动向量。
说话人识别工业界从来不指望「原始 cosine + 一个固定阈值」能work，标准做法是在
embedding 之上再加三层：**归一化打分、迟滞判决、滞后重聚类**。当前代码这三层都没有。

具体到本仓库，有四个可定位的放大因素：

1. **单窗 embedding**。`_attribute_speaker`（`subtitle_pipeline.py:862`）把整句 PCM
   一次性喂给 `embed`。语调波动是**时间局部**的（一句话里某几个字飙高），单窗
   embedding 会把这个局部扰动整个吃进去。
2. **原始 cosine 上打绝对阈值**。`SpeakerGallery.assign`（`speaker_attribution.py:88`）
   直接 `cosine_similarity >= threshold`。CAM++ 的 embedding 有很强的共同分量
   （信道 / 语言 / 录音条件），所有人的 cosine 都挤在一个窄区间里，类间可分性被压缩，
   阈值怎么调都是拆东墙补西墙。
3. **单阈值 = 没有中间地带**。低于阈值就直接 `_create()` 建新人
   （`speaker_attribution.py:111`）。没有「不确定，先挂起」这个状态，
   所以一次分数抖动 = 永久多一个 id。
4. **在线单趟、不可逆**。一旦分裂成 id 2，后面再也没有机制把它并回 id 1。

另外顺手指出一个待确认项：`providers/config.py:100` 的默认阈值是 **0.4**，
而 `scripts/diar-spike.py:63` 的默认是 **0.7**。差了将近一倍，说明这个阈值
从来没在真实数据上标定过。第 1 节就是解决这件事。

---

## 1. 第一步（不可跳过）：把问题量化

在没有分数分布之前调阈值就是抽奖。做一个标定脚本
`scripts/diar-calibrate.py`：

**输入**：一段真实直播 clip（≥10 分钟，含你说的「同一人不同语调」片段）+
`asr-probe.py` 的事件时间线 + 一份人工标注（每句一个真实说话人标签，用 CSV 就行，
标 100~200 句足够）。

**输出**：

| 指标 | 含义 | 期望 |
|---|---|---|
| 同人 pair cosine 分布（均值 / p5 / p1） | 语调变化能把分数拉到多低 | 看 p1，这是阈值的真实下界 |
| 异人 pair cosine 分布（均值 / p95 / p99） | 混淆风险 | 看 p99 |
| 两个分布的重叠区 | 单阈值到底能不能分开 | 重叠越大越说明必须上归一化 |
| EER 与对应阈值 | 当前 embedding 的能力上限 | 作为后续所有改动的 baseline |

再按「时长分桶」重算一遍（<1.5s / 1.5–3s / >3s），你多半会看到 <3s 桶的同人分数
明显更散 —— 这直接支撑第 2.1 节的多窗聚合。

**这份数字是后面每一步的验收基准**：任何改动都要能报出「同人 p1 从 X 抬到 Y，
异人 p99 没动」，否则就是自我感觉良好。

---

## 2. 五层改动（按投入产出比排序，可独立上线）

### L1 输入侧：让 embedding 本身更稳（改动最小，收益立竿见影）

**L1.1 多子窗聚合 —— 对「语调波动」最直接的解药**

把整句切成滑动窗，逐窗 embed，L2 归一化后取平均，再归一化：

- 窗长 2.0s，hop 1.0s
- 句子短于 2.0s：退化为单窗（保持现状）
- 聚合用 **归一化后平均**；如果标定发现有离群窗（BGM 冲入、半句重叠），
  改用 **medoid**（选与其他窗平均相似度最高的那个窗），更抗污染

原理：语调扰动在时间上是局部且零均值的，跨窗平均把它平掉；
说话人身份分量是全句一致的，平均后被保留。这一条通常能把同人分数方差砍掉一半。

改动点：`diar_sherpa.py` 加 `embed_pooled(pcm) -> list[float]`，
`SubtitlePipeline._attribute_speaker` 改调它。`SpeakerEmbedder` Protocol
（`subtitle_pipeline.py:52`）加一个可选方法，pyannote 那侧同样实现即可。

**L1.2 响度归一化**

embed 前把切片 RMS 归一到固定电平（如 -23 LUFS 近似，简单做法：按 RMS 缩放到
目标幅度，峰值 clip 保护）。音量本身就是「语调变化」的一个维度，
消掉它等于免费去掉一个变化源。

**L1.3 切片内再做一次静音裁剪**

ASR 的 `audio_start_ms/audio_end_ms` 段首尾常带静音和呼吸。
用能量门限（帧 RMS < 全段 RMS 的 -30dB）裁掉首尾，并丢弃中间超过 0.5s 的静音块
再拼接。有效语音不足 1.0s 的直接不 embed，走「继承 / UNKNOWN」路径。

**L1.4 补一点上下文**

`diarizationContextSeconds` 默认是 `0.0`（`subtitle_pipeline.py:330`）。
标定脚本里试 0.15~0.3s，用一点点前后文换更长的有效语音；但要注意别把
上一个说话人的尾音吃进来（`docs/overlapping-speech-research.md` 里那类风险）。

---

### L2 打分侧：从「原始 cosine」换成「归一化打分」（本方案的核心）

**L2.1 全局均值中心化（必做，10 行代码）**

维护一个所有 utterance embedding 的滑动均值 `μ`（用 EMA 或最近 200 条的均值），
打分前做：

```
e' = normalize(e - μ)
```

这是 speaker verification 的标准前处理。CAM++/pyannote 的 embedding 里有一个
很大的、与说话人无关的共同分量（信道、语言、房间、编码），它把所有 cosine
一起抬高并压缩类间距离。减掉它之后，同人 / 异人两个分布会明显拉开，
**同一个语调变化在中心化后跨过阈值的概率显著下降**。

冷启动：`μ` 样本数 < 20 时不启用，直接用原始向量。

**L2.2 AS-Norm（自适应分数归一化）—— 把「阈值」从绝对量变成相对量**

准备一个 cohort：离线从任意多说话人音频抽 200~500 条 embedding
（不需要标注，不需要跟你的直播同源），存成一个 `.npy` 随模型一起放
`vendor/models/diarization/`。打分时：

```
s_raw   = cos(e', c')                       # e'=当前句, c'=候选说话人中心
top-K   = cohort 中与 e' 最相似的 K 条 (K=30)
z_e     = (s_raw - mean(cos(e', top-K))) / std(...)
top-K'  = cohort 中与 c' 最相似的 K 条
z_c     = (s_raw - mean(cos(c', top-K'))) / std(...)
score   = 0.5 * (z_e + z_c)
```

判决用 `score`（一个 z 值，典型阈值 1.2~2.0，由第 1 节标定确定）而不是 cosine。

好处正好命中你的症状：当某句因为语调变化整体「偏离」时，它对 cohort 里
**所有人**的相似度会一起下降，z-score 把这个整体漂移除掉了，
剩下的才是真正的说话人差异。这是不换模型的前提下**收益最大的一步**。

**L2.3 （可选）LDA 降维**

如果你能积累 ≥ 每人 20 句的标注数据，训一个 LDA 投影（192维 → 100 维左右），
把类内方差压掉。收益大但需要标注，排在最后。

---

### L3 决策侧：把「一次判决」换成「迟滞 + 先验 + 确认延迟」

改造 `SpeakerGallery.assign`：

**L3.1 双阈值迟滞**

```
score >= τ_new_block   -> 归入 best_id（宽松，倾向合并）
score <  τ_new_allow   -> 建新说话人（严格，倾向不新建）
中间地带               -> 返回 PENDING，不建新人也不改判
```

`τ_new_allow` 明显低于 `τ_new_block`（比如 z 阈值 1.2 / 0.4）。
中间地带的句子：如果 L3.2 的轮次先验支持，就归给 `last_speaker`；
否则挂 `UNKNOWN`，等 L4 的重聚类回填。

**当前单阈值结构（`speaker_attribution.py:101-111`）就是「换语调 = 立刻多一个人」
的直接原因，这一条必改。**

**L3.2 轮次先验（turn-taking prior）**

换人是有代价的事件。用与上一句的间隔 `gap = begin - prev_end` 给 `last_speaker` 加分：

- `gap < 0.4s`：`score(last_speaker) += bonus_high`（几乎不可能是别人抢过去）
- `0.4s <= gap < 1.5s`：`+= bonus_mid`
- `gap >= 1.5s`：无加成

bonus 幅度用第 1 节的标定数据定（大致取「同人分数 p25 与 τ 的差」量级）。

**L3.3 新说话人确认延迟**

新 id 需要**累计 2 句、总有效语音 ≥ 3s** 才对外发布；在此之前标为 tentative，
cue 先不着色（或沿用继承色）。这条特别有效：语调抖动通常是**一次性**的，
连续两句都稳定偏离同一方向才可能是真的新人。

本仓库天然适合这么做 —— 归属本来就是 late-fix 的
（`_attribute_speaker` → `store.update(cue_id, speaker=...)`，`subtitle_pipeline.py:888`），
再晚一句定稿没有额外架构成本。

**L3.4 修掉 exemplar 池的中毒风险**

现在 `assign` 对 exemplar 取 `max`（`speaker_attribution.py:96-97`）。
一条脏 exemplar（含 BGM、含重叠语音）会**永久**把别人的句子吸过来。
加准入门槛：只有 `score` 高于一个较严的值、且有效语音 ≥ 2s 的 embedding
才准进池；池子从 `deque(maxlen=5)` 扩到 12~16 条。

---

### L4 后处理：滞后重聚类，把已经分裂的 id 缝回去

在线单趟判决**必然**会分裂，L1~L3 只能降低频率，不能归零。所以需要一个兜底：

每积累 20 句 或 每 30s，对现有各 id 的 exemplar 池跑一次
**层次聚类（AHC，average linkage）**：

- 计算 id 两两之间的类间平均相似度，以及各自的类内散度
- 若 `inter(A,B) >= τ_merge`（比 `τ_new_block` 更严的合并阈值）
  且两者时间上没有**重叠发言**，则判定 A、B 是同一人
- 合并：保留编号较小的 id，把另一个的 exemplar 并进来，重算中心

「时间上没有重叠发言」这个约束很重要 —— 真正的两个人在直播里几乎一定会
有一次接近同时开口，而分裂出来的假 id 永远不会跟本体重叠。这是一个几乎零误伤的护栏。

**合并后要回写历史**：`SubtitleStore` 已支持 `update(cue_id, speaker=...)`，
新增一个 `remap_speaker(old_id, new_id)` 批量重写已发出的 cue，
并通过现有的 cue 更新通道广播给 `web-player`，让它把颜色改回来。
`player.js` 那边只需要处理「同一 cue 的 speaker 字段变了」这一种情况。

这一层是**方案里最能直接消除用户可见症状的一步**：即使前面几层漏判，
用户看到的也只是「颜色几秒后自动改正」，而不是「一个人两种颜色一直并存」。

---

### L5 （若场景允许）多中心 profile / 预注册

直播的主播是固定的，这给了一个降维打击的机会：

- 离线给已知说话人录 5~10 段**覆盖不同语调**的样本（正常讲话、激动、小声、笑场）
- 对这些 embedding 跑 k-means，K=3~5，得到每人一组 **sub-center**
- 匹配时取 `max over sub-centers`

这直接把「一个人有多种语调」建模成「一个人有多个中心」，而不是指望单个中心
覆盖全部变化。当前的 exemplar bank 已经是这个思路的雏形，L5 是把它做实：
从「最近 5 条」升级成「k-means 覆盖式子中心 + 持久化 profile」。

配套：`providers.json` 加 `speakerProfiles` 字段指向 profile 文件，
`scripts/enroll-speaker.py` 负责录入。

## 3. 落地顺序与验收

| 阶段 | 内容 | 预计工作量 | 验收 |
|---|---|---|---|
| **P0** | 第 1 节标定脚本 + 标注 150 句 | 0.5 天 | 拿到同人/异人分数分布、EER、最优阈值；确认 0.4 vs 0.7 用哪个 |
| **P1** | L1.1 多子窗 + L1.2 响度归一化 + L1.3 静音裁剪 | 0.5 天 | 同人分数 p1 抬升，异人 p99 不动；EER 下降 |
| **P2** | L2.1 中心化 + L2.2 AS-Norm | 1 天 | 两个分布的重叠区显著缩小；EER 再降 |
| **P3** | L3 迟滞 + 轮次先验 + 确认延迟 + exemplar 准入 | 1 天 | 在标定 clip 上「同人被拆成多 id」的次数归零或个位数 |
| **P4** | L4 重聚类 + `remap_speaker` + 前端重着色 | 1 天 | 人为制造分裂后，30s 内自动合并且历史 cue 颜色回正 |
| **P5** | L5 预注册（可选） | 1 天 | 主播全程单一 id，跨场次 id 稳定 |

**建议至少做到 P3；P4 是保证「用户看不到症状」的关键，强烈建议一并做。**

统一的端到端验收指标（在同一段标定 clip 上跑）：

- **说话人分裂率**：真实说话人数 / 系统输出 id 数，目标 ≥ 0.9
- **归属准确率**：逐句正确率，目标 ≥ 92%（非重叠段）
- **色彩churn**：同一真实说话人的连续发言里颜色变化次数，目标 ≤ 1 次 / 10 分钟
- **延迟**：`_attribute_speaker` 端到端耗时，多窗聚合后不应超过 2× 现状
  （CPU 上 CAM++ 单窗约十几 ms，2s/1s 的窗对一句 6s 的话是 5 窗，仍在可接受范围）

现有测试 `tests/test_speaker_attribution.py` 要同步扩：
「同人分数抖动一次不应新建 id」「PENDING 状态不改判」「重聚类能合并两个同源 id」。

## 4. 陷阱

- **不要只调阈值**。调低阈值 = 减少分裂但增加混淆（两个人同色），
  在没有 L2 归一化的前提下这是零和的。这就是为什么 0.4 和 0.7 两个默认值
  都不对 —— 单阈值本身就是错的抽象。
- **AS-Norm 的 cohort 不能只用本场说话人**。人太少时 z-score 方差估计不稳，
  必须有离线 cohort 打底。
- **L4 的合并会改写已经播出去的字幕颜色**。要确认这个体验可接受
  （我认为可以：「颜色几秒后自动修正」远好于「一个人两个颜色」），
  并且前端 `subtitle-scheduler.js` 对同一 cue 的二次更新要幂等。
- **重叠语音是另一个问题**，本方案不解决。见
  `docs/overlapping-speech-research.md` —— 重叠段的 embedding 是两个人的混合，
  它会污染 exemplar 池，所以 L3.4 的准入门槛不是可选项。
- **`_update_center` 的 EMA 没有重归一化**（`speaker_attribution.py:150`）。
  cosine 本身尺度无关所以现在无害，但引入中心化后中心向量会带偏移，
  改动时记得每次更新后 L2 归一化。
- **多窗聚合后 `is_ready` 的短音频保护要逐窗判**，不要让一个不足长度的尾窗
  抛异常把整句归属废掉（现在 `_attribute_speaker` 的 except 会让 cue 保持 `speaker=None`）。
