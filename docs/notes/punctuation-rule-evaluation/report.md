# 简单标点规则：日语／英语真实直播记录回放

日期：2026-09-07。结论：4 秒内部标点规则显著减少本批英语长字幕，且未发现计算开销增加；但逗号并不保证分句完整，短尾巴和不完整短语确实出现。适合作为简单候选，不能宣布语义切分质量已经通过。

## 方法与范围

- 使用已有日语四路、英语四路 Soniox `stt-rt-v5` 实际识别记录，按原始到达顺序回放。不是本轮重新开启直播；没有调用 ASR、翻译或模型 API。
- 八路总音频 101.75 分钟。每路前 60 秒试采不计入主表，正式可用音频合计 93.75 分钟。日语新闻 ja-D 仅有 645 秒且采集中断，没有尾部确认，作为不完整样本保留。
- 当前逻辑读取本轮工作区代码，而非旧采集时的字幕结果。候选继承同一 CaptionChunker，只替换边界判断；文字确认、说话人处理、1.2 秒已结束残句宽限、时间戳、收尾逻辑相同。
- 候选：明确句末 `. ! ? 。！？` 不要求凑时长；内部标点 `, ; : 、，；：` 到达时，标点前自本条开始的音频跨度达到 4／5 秒才切。选择最早合格标点，切后重新计时。不是再等待 4／5 秒。
- 标点只能在已有 ASR 单元边缘切。格式保护包含数字内部的小数／千分位、网址、邮件、多点缩写；已到达的闭引号／括号附在左边。没有加入词性或语法模型。普通缩写、列举数字仍非全面覆盖。
- 候选不使用当前日语词法判断，也不保留“已到达的短整句优先覆盖内部切点”规则。因而对比包含句末信任策略的变化；另增加“仅句末标点”对照，帮助区分这一因素与内部标点的收益。
- 有新事件之前，按真实单调时间处理已设的残句期限。末尾额外 3 秒及强制 flush 用于文字守恒，强制收尾字幕不计入主表；未确认的 ASR 尾部不在守恒承诺中。
- 原始记录只在当时到达后进入算法，不借用后面的完整句子；本轮没有播放全部音频进行人工标注，没有翻译或浏览器上屏测试。

## 是否真的提前切出

为避免“同一次提交拆成多条”造成统计假象，按相同原始 ASR 单元配对，比较其被切句器释放的时间。只计正式区间、非收尾、含非空白文字的单元。单元不等于句子；不同语言 token 粒度不同，比例不能跨语言比较。等待从该单元被确认接受时算起，不包括之前的 ASR 等待，也不包括翻译／播放器。

|语言|方案|配对单元|提前 / 不变 / 推迟|确认后等待 P95：当前 → 候选|平均提前|
|---|---|---:|---|---|---:|
|ja|标点 4 秒|10545|2407 / 8038 / 100|1.41 → 1.20 s|0.27 s|
|ja|标点 5 秒|10545|2370 / 8084 / 91|1.41 → 1.20 s|0.26 s|
|en|标点 4 秒|8862|907 / 7941 / 14|6.34 → 4.24 s|0.40 s|
|en|标点 5 秒|8862|629 / 8192 / 41|6.34 → 5.62 s|0.30 s|

4 秒候选英语约 10.2% 单元提前、0.16% 推迟，其余不变。最大提前 13.922 秒是个别长句中的前部内容，不是全场平均改善。推迟的例子：当前会先切 `And I asked him,`，新规则因不足 4 秒继续等待，相关前部内容推迟 4.125 秒；这是避免短条的代价。

日语中，一个新闻长句虽然拆成两条，二者仍在同一帧 551.562 秒附近切出，所以只改善长度，不改善最早提交。反之英语电竞 17.40 秒长句的第一段从 353.219 秒提前到 339.297 秒，确实提前 13.922 秒。

4 秒是寻找可用标点的起点，不是最大字幕时长。英语剩余 10.98、11.34 秒两条长字幕，均没有门限之后的内部标点；单靠此规则无法继续切短。

## 文字反例与质量限制

检查了新增内部切点的左右文本并挑出以下明确风险。这是文本层面的定性复核，不是母语者听音评测，也没有以抽样比例冒充总体准确率。

- 日语 ja-A：`で、学校の、学校1の美人の、 | なんか、女の子の彼女がいて…`。前段 7.26 秒，结尾相当于“学校里最漂亮的……”，后面的名词尚未出现。4 秒和 5 秒都切在这里；提高到 5 秒并不能避免这个问题。
- 日语 ja-D：`…海に流れてすごく、 | 海も抹茶茶になってたんで。`。结在“非常……”这样的修饰语后，不是完整分句。
- 英语 en-D：`And the CDU, the party of Friedrich Merz, the traditional conservative party, | has stuck to it.`。主体与谓语分开；两边有上下文不等于前半已经能完整翻译。
- 英语 en-B：`…where it’s either you send 3, | 4 guys in middle…`。原记录是 `3, 4` 的口语数量表达。格式保护挡住 `1,000` 的词内切分，但无法自动识别这个有空格的数量组合。
- 新出现短尾巴：英语 `Dougie.`（0.30 秒）、`I think.`（0.42 秒）、`right?`（0.12 秒）、`in Germany.`（0.60 秒）。日语 `毎回。`、`え。` 等也可能单独出现。语音跨度不是显示时长，实际是否闪烁还取决于字幕调度。
- 相比当前分组，4 秒候选产生了 10 条新的英语不足 1 秒片段、40 条新的日语不足 1 秒片段；主表净增分别是 9／18 条，因为有些旧短条被合并。并非所有短句都有问题，例如完整回答也可能很短。

因此，本轮支持“减少过长字幕”，不支持“保证在分句末尾切”。如果业务接受在逗号处暂时停顿，这个候选有价值；若坚持每条都至少是完整分句，这个规则仍不满足要求。

## 性能与正确性

- CPU 离线回放，当前逻辑先预热日语词法分析器，输入预先解析。没有网络或模型推理。回调计时包含本实验追加的单元记录／断言，不能当成生产精准性能预测。
- 每路完整回放逐一核对原始已确认文本（按 speaker、NFKC 去空白）、单元不丢不重、顺序、原始时间边缘。四种方案均通过；不可据此宣称说话人识别正确。
- `check_rule.py` 验证门限、切后重新计时、到达时间与语音时间区分、短句末、无标点不硬切、闭引号、分片小数／千分位、数字句末 endpoint、未来续句不改变已切前缀。合成时间只用于契约检查，不混入真实统计。
- 原始识别记录和当前两份生产切句源码保存 SHA256；回放前后源码哈希不变。没有修改生产代码，没有重启服务，也没有运行与本实验无关的生产测试套件。

## 建议

在这批样本中，优先选择 4 秒作为简单标点候选，而非 5 秒。日语新闻某个合理逗号落在 4.98 秒，5 秒规则错过后把整条保留到 12.48 秒，4 秒规则则分为 4.98 和 6.84 秒。门限位置对具体结果有明显影响，单调提高门限也不保证每一条最大跨度单调变化。

暂不自动部署。若下一步采用，最小的后续实验应优先验证：当同一批已确认文字里已经有极短句尾时，能否保留整条避免孤立尾巴；不要为此额外等待尚未到达的后文。该保护尚未实现或测试。

不建议为了消灭所有反例立刻扩张到大量语言专用规则。需要明确接受“较长字幕可以在逗号处暂时分开”的质量取舍；若要求严格分句，不能用本轮长度改善掩盖上面的语义反例。

## 复现与产物

- `experiment.py`：四种规则的流式记录回放和守恒检查。
- `check_rule.py`：实验规则的窄范围契约验证。
- `results.json`：汇总、原始源码与记录哈希。
- `*-current.json` / `*-punct4.json` / `*-punct5.json` / `*-terminal_only.json`：每次字幕切出时间与原 ASR 单元映射。
- `changed-examples.json`：全部发生变化的对照窗口，不只保留改善案例。
- `review.html`：可筛选来源的逐条对比页，提供原始本地录音片段播放；播放控件仅用于人工复核，不表示已经听音验收。
- `write_report.py`：从实测 JSON 生成本报告与对比页。

在仓库根目录设置 `$env:PYTHONUTF8="1"`，依次运行 `python .scratch/punctuation-rule-evaluation/check_rule.py`、`python .scratch/punctuation-rule-evaluation/experiment.py`、`python .scratch/punctuation-rule-evaluation/write_report.py`。依赖与当前切句器相同，无新增包。
