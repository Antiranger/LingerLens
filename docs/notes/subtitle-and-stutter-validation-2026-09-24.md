## 卡顿报告复核

原报告的前后数据支持“自续诊断 rAF 是显著的性能放大因素”。但修复后的运行换了直播源，不能据此确认它是所有严重卡顿的唯一原因。“这是探针问题、不是应用功能缺陷”的分类不成立：随应用交付的探针也是应用代码。

`direct_rendering_display_compositor`、`trees_in_viz` 的状态不足以单独证明特定合成工作位于浏览器主线程，也不足以证明 DWM/鼠标合成被饿死。V8 idle 主要排除所采 JavaScript 执行，不能独立定位原生栈。进程 CPU 时间包含多个线程，不等于某一个线程或核的利用率。

被动 rAF 计数为零，仅表示包装器未观测到 JavaScript 回调间隔；视频、CSS 动画和显示合成仍可运行。稀疏业务回调产生的大间隔也不应直接统计成掉帧。未认证请求的 HTTP 403 证明的是请求守卫可响应，不是受保护业务处理器已完成工作。

整改保留被动探针，不重放可能使整机失去响应的高刷新率主动探针。补充：探针卸载只还原自身仍占有的函数；关闭日志时请求直接透传且媒体响应不增加统计流；缓存代理的首包计时与整包耗时分开；请求标签数量有界；XHR 与 fetch 均可正确还原。

装饰方块仅动画 transform/opacity，不再动画背景颜色。跑马灯默认暂停，仅在视口内运行；文档隐藏时暂停装饰动画。此项是成本控制，不等于已经独立复现和证明原始整机冻结的唯一根因。

## 字幕实现

- 视频帧是显示时钟，固定 150 毫秒提前量不再参与调度；结果传输不是字幕时钟。
- 原文预览以带时间戳的稳定文字提前下发，播放器按帧准入，不必等起点之后的播放头往返请求。缺失或不可信媒体锚点仍拒绝伪造时间。
- 预览按数量有界；未来说话人的文字不覆盖当前说话人；同文重复短句以 Provider item 与代次区分，不能被前一句延长显示误吞。
- 原生 Qwen 使用 `conversation.item.created.previous_item_id` 和 `response.output_item.added` 关联输入段、输出段和 response；有 ID 的消息不再用 FIFO 猜测。乱序关联等待有容量/字节限制。
- 带 ID 的 `response.text.done` 不是最终成功；等待 `response.done` 的状态后，取消、失败、未完成响应不发布最终译文。原文完成与翻译完成独立，二者任一先到都不能把另一边提前关闭。
- 提供原生翻译到独立 MT 的显式可选兜底；不偷偷增加收费调用。不能可靠切分的原生译文不按字数或同时到达的比例硬配。

## 本轮收费接口与真实播放器证据

声画标记实验不是 mock ASR：实际付费 Provider、生产 SubtitlePipeline、两路真实 TCP、FFmpeg 封装、生产网页播放器。固定 15 秒目标延迟，25 fps 英文参考视频，每 5 秒重复同一句话，观察 52 秒，播放覆盖 7 个句首标记。重复短句刻意用于检查错误去重。输入固定，服务返回结果并不保证逐次相同。

Qwen 3.8 的问题不是统一固定偏移：有的短段没有给出文本，后段最终文本却包含前段内容；当前段 VAD 起点不能代表这段合并文本的真正起点。增加到 800ms 并同时发送新旧 session 字段、关闭响应打断，以及采用文档中的 nested speaker_detection 字段两项额外 40 秒实验仍出现合并/缺句。不存在证据支持对所有句子统一减一秒。保留 3.8 为实验性配置，不放进四条优化默认路径；不改写用户旧配置中的模型。

从实际播放的 HLS 再解码音频，与原参考 PCM 做独立互相关：相关系数 0.999961，实际音频起点相对原夹具后移 80ms。四条通过路径在计入该变化后仍与声音标记同帧。这里的“0ms”是 25 fps 视频采样下同帧，不是声卡、显示器物理输出或任意自然语言音节的连续时间零误差承诺。Qwen 3.8 最近 cue 的距离不能替代语义匹配；未匹配的 27 秒标记不得伪装成提前 3.72 秒。
