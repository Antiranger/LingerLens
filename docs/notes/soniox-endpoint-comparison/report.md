# Soniox 结束标记 vs 稳定句末 vs 主动切分

本轮为历史真实 ASR 到达流的离线对照，不调用 API，不更改正式字幕运行路径。

## 三组具体行为

- A：只等 Soniox `<end>` 自然结束标记，立刻输出该 item 的全部已确认文字；不同说话人保留独立字幕。没有额外 1.2 秒残片等待，没有跨 item 合并。
- B：稳定文字出现句末标点就输出；自然结束时立即输出残余。不按逗号主动切。复用格式/日语窄保护；没有完整句法保证。
- C：上一轮选出的 4 秒标点＋保护规则；保留现有接收、残片期限和跨 item 续接行为。这是已验证候选逻辑，尚非运行中的默认。

B 与 C 除逗号策略外，还存在结束时残余立即交出的差异，不能把等待差异全部归于逗号。A 使用的是语音段结束标记，不是每个 `is_final` 文字批次，也不是每个句号。

## 数据范围与公平性

八路 ja-A/B/C2/D、en-A/B/C/D，共 101.75 分钟历史录音，前 60 秒/路排除。此次仅对自然 `<end>` 已闭合内容比较，排除 `<fin>`、EOF、缺失结束和人为 flush。ja-D 采集失败尾部仍单独记录。故字幕条数与上一轮略不同。

A 的归组从同一套接收账本的原始 item 和说话人构建；C 复现上轮输出并逐条断言一致。B 接收账本同样一致。配对等待比较固定为日语 10,532、英语 8,806 个相同非空识别单元。字幕长度按各自产物起点≥60秒筛选，窗口边缘可能有少量不同；延迟以相同单元配对为准。

统计的等待从接收层接受稳定单元到字幕交出，不包含此前 ASR 稳定延迟、翻译和播放器。归零等待表示已确认内容随结束同批到达，不表示端到端零延迟。

## 原始记录核对

en-D item 34：音频 413.94–524.76 秒，共110.82秒；自然 `<end>` 在回放到达时间525.703秒收到。原始 utterance_final 文本是包含多个句号的长发言，非一条语法句子。C 第一段在429.25秒已经交出。若等结束标记，同样的第一段会再等96.453秒。item 38 还有另一例107.16秒长段，其首段可提前100.266秒。

这些是此配置/样本下的极端记录，不是 Soniox 每段都要等一两分钟，也不是 ASR 算一句话用了110秒：中间文字已陆续稳定，迟到的是整段结束标记。

ja-D item 101：14.82秒的一段中包含“よろしくお願いします。”等多个句子，C 最早一条提前8.937秒交出。日语同样存在需要介入的长段，但比例低。

## 已确认以后还要不要等

对比A，C的日语单元381个更早、209个更晚；英语3688个更早、183个更晚。变晚说明已有最终文字仍可能被本地保护/残片续接延后，不能声称当前候选在每条上都比原生结束更快。B的这个对照中两种语言均没有单元比A更晚，因为结束时直接释放残余。

日语已稳定内容有9630/10532个在A下等待为0；英语4425/8806个为0。这只是接收层稳定单元与结束同时到达的统计，不是模型首次识别时刻，也不表示最近送入的全部音频都已经稳定。

## 结论

不能只依赖语音结束标记，英语新闻/快速解说的长连续发言会出现明显阻塞。也不应把每次 final token 返回当一句字幕。更合适的基本流程是：稳定句末先交出、自然结束立即交出残余；4秒弱标点切分负责长句。日语大部分原生短段应直接保留，不需要为了达到目标长度再强行拆分。

该结论不等于应立即删除所有语言保护；结束标记也不保证语法完整，立即输出与修饰语保护仍有取舍。B的语义质量没有独立人工盲评，本轮不部署。
