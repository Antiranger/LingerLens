# 翻译不等前句：原文上下文与独立字幕时间

日期：2026-09-06。

用户要求：切好的句子立即翻译；前句原文即可作为上下文，无须等待前句译文；慢句不能拖延之后所有字幕，需要恢复到正确播放位置。

## 根因与修改

旧实现虽然有四个 translation worker，但 `_translation_pending` / `_translation_known` 把同一 generation 的请求串起来，等所有前序翻译完成才允许后序启动。该策略为了取得直接前文译文，引入了可以避免的连锁等待。新增控制服务测试先在旧代码上因后句不能启动而超时，再在修复后通过。

移除了前后句依赖链，保留既有默认四路并发、队列上限、每句独立截止时间和降级逻辑。截止时间从入队算起，排队不会续期；已过期的排队工作直接结束为原文状态，不再发出网络请求。四路均忙时仍可能等待，因此不宣称“任何负载都零排队”。

字幕入队时立即记录原文，成功后补上译文；翻译请求按既有范围和数量限制读取前文快照。未完成前文为 `(source, None)`，通用 prompt 明确标记 SOURCE ONLY，只用于理解，禁止重复输出。已有译文则同时提供，不会为了补齐上下文等待。

当前 OpenAI 兼容 Gemini profile 支持这一 prompt。Claude / Google GenAI 共用同一 prompt；专用 Qwen-MT 的 tm_list 只能表达真正的原文/译文对，因此过滤未翻译条目，不伪造目标文字或新协议字段。

显示端原本就使用每句真实说话时间，不按翻译完成次序重排或推迟后面的时间。补充修复一处例外：过期字幕的 catch-up 补显示在新一句开始时让位，且不会在新一句结束后重新冒出。不同说话人的真实语音重叠仍保留；未找到早期 ASR 分句边界的问题不在翻译层伪造解决。

## 实验

命令：`python .scratch/translation-no-predecessor-wait/experiment.py`

固定输入：上一轮 `clause-segmentation-v2/live-soniox-evidence.jsonl`，120 秒直播录音的真实 Soniox observations，按原到达时刻回放。正式 pipeline / context / worker 调用当前真实翻译 profile `gemini-3.7-flash-low`。没有再次请求 ASR，没有使用 HLS/浏览器实际播放。确认新旧字幕原文、次序和 speaker 相同。

| 指标 | 结果 |
|---|---:|
| 字幕数 / 翻译成功 | 42 / 42 |
| 语音起点后 15 秒内译文就绪 | 42 / 42 |
| 最大同时翻译数 / 配置并发 | 3 / 4 |
| 使用未翻译前文原文的请求数 | 18 |
| 排队 P50 / P95 / max | 0 / 0 / 0.015 秒 |
| 翻译请求 P50 / P95 / max | 1.485 / 3.203 / 4.766 秒 |
| 起点到译文就绪 P50 / P95 / max | 5.242 / 12.140 / 14.818 秒 |

旧实测排队 P95 1.234 秒、max 2.172 秒。新测试的 0 秒表示测量精度下为零，不能理解成无任何事件循环调度开销。云服务延迟不同、prompt 上下文内容也不同，因此不能把两次总延迟直接作为纯调度变化的因果对照；本轮整体就绪并未比上轮更快。消除前序依赖的因果验证来自受控测试；真实服务验证它能并发运行并接受原文上下文。

## 回归与限制

- 第一句受控阻塞时，第二、三句先完成，第四句仍能启动，原始显示时间不变；上下文包含第一句原文及二、三句译文。
- 四路占满时第五句等待，任一路完成就立即释放给第五句，无须等第一句。
- 单路饱和、后句过期后不再发出该请求，新鲜句子取得自己的截止时间并正常完成。
- 上下文从原文升级为译文不改变已发请求；排除当前、未来和其他会话；保留数量/媒体时间窗口。
- 晚到前句不改变后续字幕开始时间；过期补显示让位且不会复活；原有真实重叠语音测试通过。
