# 02 — 全屏字幕浮窗与目标总延迟

**What to build:** 让字幕在 LagLingo 全屏播放时继续显示，并成为可拖动、可持久化定制的浮窗；同时把内部“下载后额外延迟”改成用户可理解的“目标总延迟（秒）”数值输入，要求大于 10 秒、默认 15 秒，并保持实际测量值与目标值分开显示。

**Blocked by:** None — can start immediately.

**Status:** complete

- [ ] 先在浏览器 seam 写失败测试：点击 LagLingo 全屏按钮后，fullscreen element 是包含 video 和 subtitle window 的播放器舞台，而不是裸 video；退出全屏后字幕继续正常调度。
- [ ] 提供 LagLingo 自己的全屏控件，并在浏览器允许时隐藏/避免裸 video 原生全屏入口；以真实 Chromium smoke 验证全屏字幕可见。
- [ ] 字幕浮窗有明确拖拽手柄，位置使用播放器归一化坐标持久化；窗口 resize、进入/退出全屏和恢复设置时都被限制在可视边界内。
- [ ] 除拖拽手柄外，字幕内容不拦截播放器控件；提供键盘可操作的位置调整或预设位置，以及恢复默认按钮。
- [ ] 字幕设置增加透明度、字号/缩放、中文字幕颜色、原文颜色；现有中日双语/仅中文/仅原文和时间偏移继续工作。
- [ ] 样式和位置保存到本机偏好，下次打开页面和切换直播时恢复；损坏或越界的旧值安全回退默认值。
- [ ] 先在 loopback start/status seam 写失败测试：`targetDelaySeconds` 缺失时默认 15，输入 10 或以下被拒绝，合法值能启动并在状态中同时返回 target 与 actual/estimated delay。
- [ ] UI 把字段改名为“目标总延迟（秒）”，使用可直接输入的 number 控件，`min=11`、默认值 15，并提供简短说明：这是希望落后真实直播的总时间，不是单个内部缓存。
- [ ] 服务端用统一的目标延迟合同协调发布预算和浏览器 live-sync 距离；不得再把 `publishDelaySeconds` 作为用户配置概念暴露。
- [ ] 字幕预算不足的一键建议更新目标总延迟，并继续限制在合法范围；实际测量的估计总延迟保持独立指标。
- [ ] 覆盖刷新恢复、全屏切换、拖拽夹取、样式持久化、非法延迟和合法延迟启动的红→绿测试；现有 cue scheduler 与播放稳定性测试保持绿色。
