## 0. 依据、事实与推论的边界

完整阅读了简报以及同分支的审计、88 项配置连线表、已有计划。读取 `2225eee` 至指定分支的比较结果，只用于确认版本边界：差异文件均在 `docs/`，不重新判定审计缺陷。另读测试入口，以及预算、恢复和状态输出接口，使验收能够落到现有结构上。

**接受九条已复核技术断言；决策清单覆盖简报 §3 的十个编号。两者数量不相同，不构成需要重做审计的理由。**

本计划把简报内联的运行数字作为有效决策输入，不声称独立看过其原始日志。尤其保留以下限定：

- A1、A2 的真实观测次数为零，不等于触发概率为零。
- 75 是**已记录的失败事件行数**（M1 逐文件点数得出），不是失败总数，也不是所有字幕的失败率。按**异常来源**重分后是 **49 裸超时 / 26 链耗尽**（其中 9 行记录为兜底收到已过期期限），不是早先按关键词分出的 57/13/9——那个口径把 `RuntimeError: … A: TimeoutError` 这类行也并进了裸超时。（`D0` 更正，见文首修订记录。）
- 更要紧的是这个计数本身是**下界**：`subtitle_pipeline.py:1360` 对每一次 provider 阶段失败都累加计数，但 `:1364` 只在 `_translation_failure_recorded` 为假时写日志，而该标志只在一次**成功**翻译之后（`:1333`）复位，**连续失败被折叠成一行**；队列到期那条路径（`:1337`）则只加计数、完全不写日志。因此这 75 行不能与 `/api/status` 的 `translationFailures` 互相充当分子或分母。
- B2 已被证实是预算边界缺陷，不意味着修改后能够挽回全部九次失败，更不意味着总失败率下降九个百分点或十二个百分点。
- 当前 Soniox 启用端点检测，不能把无端点合成输入的耗时直接当作当前直播的持续负载。
- 4.65 秒是一次 **rAF 回调空档**。独立采样仍按约五秒节拍执行，因此它**不能排除采样之间的短停或显示系统冻结**；`longTasks=0` 只说明未观测到该定义下的长任务，不等于任务一定获得了调度；`currentTime` 在推进也不证明画面真的被呈现。采用审计中的窄结论：没有可见性、遮挡等字段时，不把它升级为已经证明的实际视频停帧、DWM 故障或整机冻结根因。rVFC 同样是**呈现给合成器的回调元数据**，不是物理屏幕扫描证据。

## 2. 顺序、前置条件和与 Stop 会话共存的方式

### 2.1 先解决作者归属，不对工作区做“清场”

建议用户对简报 §6.1 作如下选择：**让 Stop 会话的作者先保存一个可回退提交，包含新文件 `win_job.py`；给出提交 SHA、实际修改文件清单和尚未通过的验收；明确交出产品工作树写入权。随后才由一名整改作者继续。**

WIP 提交可以是还不能发布的还原点，不等于通过发布验收。不得由第二作者擅自 stash、覆盖或提交前一作者的改动；也不得在正在运行的同一工作树中，以“改不同文件”为理由同时写入。

用户也可以让原作者继续承担 A2。此时它仍是唯一产品作者；本计划不要求另起一个同时写入的会话。采样脚本需要更改时，同样由有归属的执行者完成，或经用户批准在独立诊断位置操作，不与产品作者争用工作树。

每项改动前有可恢复状态，每个逻辑补丁形成独立提交。不得为了取得干净基线而回退 `disable-gpu`、时钟锚点、字节时钟等已定案修复。

不接受排序 A 中“系统级调查完成后才开始关键产品小修”的硬依赖，也不把排序 B 的概率公式算成数字分数：这里没有足以给各项填入可靠触发概率的数据。A2 的灾难性依赖与低成本是单独的安全门槛；其余项目再结合实测发生、修改风险和当前路径排序。

### 2.3 Stop 会话必须自己关闭的两个集成缺口

这两个问题不转移成“本轮顺手修 Stop”的范围，而是其作者的交付条件：

1. `/api/start` 成功前抛错后，不能使 `stopRequested` 永久阻止按既有约定接入其他标签页的新会话。
2. `/api/stop` 正文挂起时，`pendingStop` 必须随有界错误完成，后续 Start 必须能有界成功或明确失败，不能永久 pending。

**请求超时不等于后端已停止。** 不能为了让 Start 测试通过，超时后直接并行启动第二个会话。旧会话确实结束后，后续一次正常 Start 应能工作；同时不能把用户刚手动停止的旧会话错误地 attach 回来。

`flush/aclose` 的共享五秒期限不自动等于整个 Stop 操作的五秒上界；`win_job.py` 的 docstring 数字也不作为本次已测得的全链路停止时延。

### 2.4 R1：PTS 回绕必须有明确归属

简报已经给出 **33 位、90 kHz 的 PTS 回绕周期约 26.512 小时**，以及跨回绕落入 `None`、再退回偏差约 4.44 秒路径的风险。它不是 A1/A2/B2 的性能补丁副作用，也不能因为不在十项表中而遗漏。

**安排一个独立的“跨回绕正确性”工作包，最迟在全天连续使用验收前关闭；在 A1 之后、低优先级清理之前评审它的修复机制。** 本轮不先改时钟算法，不以重启下载腿、定时重启会话或延长缓冲规避。

这个工作包直接继承已确认缺陷，不重新证明它存在。修复验收合同是：用接近 `2^33` 边界的合成 PTS 对和跨边界连续序列，验证合法的相对映射连续、同侧映射保持、真实断流仍被识别；不得再无声退回已知偏差路径。采用离线回放，不需要先等一次真实 26.5 小时长跑。具体时钟/epoch 机制须另经用户批准。

在该工作包未通过前，发布说明必须明确“跨 PTS 回绕的全天对齐保证尚未完成”。不能把“应用刚启动、尚未运行 26.5 小时”当作安全证明：运行时长并没有给出源 PTS 离回绕还有多远。

### 2.5 用一条工程约束约束改动，不建立“万能修复机制”

**外部资源必须有唯一所有者；一次有总期限的操作，其响应头、正文、兜底及清理责任不能在中途失去边界；每条 PIPE 必须有持续消费者或明确重定向。** 取消与资源回收应复用既有会话生命周期，不在每层重新开始一份预算。

这条规则用于审查 A1/A2/B2 和 Stop 的交界，不意味着所有操作一律五秒，也不意味着十项缺陷有同一个技术根因。B1 的历史重算、C1 的集合增长，以及日志/配置/阈值不一致，都不能靠给 await 加超时解决。本轮不创建 TimeoutManager、通用重试器、全局资源注册中心或新的恢复状态机。

## 3. 机制选择：A1、B2，以及不得代替用户作出的选择

### 3.1 A1：建议有界诊断尾部的专属 stderr 读者，待 §6.2 批准

**目的。** 排空解码器错误管道，保留解释异常停止所需的最近诊断，不建立新的日志系统。

**建议形态。** 在既有字幕任务登记体系中增加一个 stderr 消费任务，按固定大小字节块读取，只保留有上限的诊断尾部。例如 4 KiB 读取块、64 KiB 尾部可作为实施前商定的初始值；这是建议值，不是 Windows 管道容量或已有配置。尾部用于诊断，不新增高频 API 推送或持久日志管线。

**生命周期。** 解码器成功创建后随字幕任务启动；EOF 后自然退出。停止时，解码器仍可能写入期间不能先移除唯一读者，也不能先无界等待一个仍被管道阻塞的进程退出。读者回收并入交接后的既有字幕清理顺序和 deadline，不另加一段无界 `await`，也不为每个资源再续五秒。

**失败行为。** 诊断读取异常不能被悄悄吞掉后留下仍向无人消费管道写入的进程；进入已有字幕异常/终止处理。诊断格式损坏只能降级诊断，不能反向改变 PCM 数据路径。不得自动重启下载腿。

**回滚。** 单独回退 A1 提交及其任务注册、尾部状态；Stop 作者提交和其他已定案修复保持不动。回退后明确恢复了“字幕失活风险未修”的状态。

**为什么不选其他两种。** `DEVNULL` 最简单，但丢失本轮仍可能需要的解码器诊断；作为用户明确选择的应急取舍可以成立，不作为默认建议。有界文件需要定义文件大小、轮转/覆盖、关闭、清理和磁盘失败行为，不能仅用“OS 会排空”略过这些责任。在已有异步任务架构中，单个有界读者更容易把所有权限制在字幕会话内。

### 3.2 B2：建议“有可用兜底才预留；短预算直接跳主”，待 §6.3 批准

三个候选并非完全互斥：“只有可用兜底才预留”是资格条件；资格成立后，还需要选择短预算时怎么做。

本计划建议：**当确有现有规则下可尝试的兜底，且剩余时间不超过预留量时，跳过主服务，把仍然存在的总剩余期限交给兜底。** 不引入比例系数。

设原始 cue 截止时刻为 `D`，调用前剩余时间 `R = D - now`，既有预留量为 `r`：

| 条件 | 建议行为 |
|---|---|
| `R <= 0` | 不再发新 provider 请求；沿用既有到期/原文退化路径 |
| 没有可用兜底 | 不扣预留量，主服务可使用至原始 `D` |
| 有可用兜底且 `0 < R <= r` | 跳过主服务；按既有兜底顺序尝试，所有请求仍不得越过 `D` |
| 有可用兜底且 `R > r` | 主服务截止于 `D-r`；失败后兜底使用真实剩余时间，不能重置整条期限 |

“可用”仅复用当前链已有的禁用、冷却及已知输入限制等判断，不增加网络健康探测或新熔断器，不保证远端一定成功。原链已经具有禁用和冷却状态，实施时应复用，而不是另建平行状态。

**产品取舍。** 极短预算时优先争取按时出现译文，而不是保留主模型先试一次的机会。其代价是可能放弃本来能快速成功且质量更高的主模型。因此必须由用户批准，不能以“三行修 bug”为名隐去这项取舍。

**失败行为与边界。** 预算跳过不算 provider 失败，不因此使其进入冷却。取消应继续传播。全部请求失败仍走既有退化；不新增重试、并发竞速、延后展示或队列扩容。无兜底、兜底禁用/冷却等情形不能被错误地判为应该跳主。

**为何不选比例分配。** 目前没有两端在极短预算下的完成分布，比例只是新参数，还可能两边都无法完成。跳主更容易定义和用确定性时钟验证。若后续同配置证据显示这项选择明显损害按期有效译文产出或可接受质量，应撤回策略，而不是继续调比例碰运气。

**回滚。** 独立回退 `fallback.py` 的策略提交和对应回归修改；不顺手回退用户已调整的 `maxTokens=1024`。简报的“三行”是缺陷主体量级，不是为了凑行数而省略可用性判断的预算承诺。

### 3.3 另外两项人类决定

**文件归属（§6.1）**：推荐原作者保存、交接后串行实施，或原作者继续作为唯一作者。用户未指定时，产品写入停止，文档决策可以完成。

**D1（§6.4）**：推荐删除死 `RecoveryPolicy.action` 及只为它存在的赋值；不接入自动重连。若它承载需要兼容的状态 API 字段，先由用户确认兼容方式，再决定删除范围，不能直接破坏外部契约。保留真实、已有消费者的状态/原因字段，不新造同义死字段。

## 5. 验收：现有入口、具体通过条件、测量边界

### 5.1 测试入口


### 5.3 暂缓项目的重新启用门槛及未来验收

**B1。** 下一步仅限于一段用户批准的正常 Soniox 会话或已有真实消息回放：取得相邻端点间消息、token 数以及 `_map_event` 处理时长。当前端点配置不能为了制造问题而关闭。若实际出现长无端点历史，且同步处理成本占用了可感知的服务响应时间，再批准增量算法。只有合成最坏情况证据时，本轮不实现。实施后用同一消息序列比较旧/新事件输出，文本、词片段、说话人、语言、置信度、final 修订与端点语义必须一致；空新增消息不得随已消费历史线性变慢，端点后状态回收；运行 P 和 CI。当前没有原始消息或可用时长字段时，先由用户批准外部诊断包装，不在产品里暗加 profiler。

**C1。** 当前不测四个休眠适配器。用户准备启用其中之一，或者实际运行出现这些集合相关的资源增长，才针对该协议规定晚到/重复窗口并批准回收机制。未来验收是相同输入产生相同事件、窗口内重复被抑制、有效晚到修订不丢失；处理 100/1,000/10,000 条消息及更长有界重放后，保留量不再随已结束会话历史无界增长；运行 P 和 CI。

**C2。** 先使用 M1 区分队列和 provider 阶段。只有连接/TLS/代理建立被证明占有可消除的期限成本，才批准隔离的复用候选；本地十二连接不是这个证明。候选不直接进入产品，先在同输入、同端点、同配置、既定费用上限内比较总时延和按期有效完成。只有改善超过对照噪声且失败/取消/停止不退化时才允许并入；没有收益就结束该项。未来验收还包括支持 keep-alive 的本地序列请求确实复用、不同凭据/代理隔离、会话关闭后连接回收、无 session 未关闭告警、P 和 CI 通过。

上述门槛触发不等于可以立刻写新机制；依然需要先交代生命周期、失败行为、回滚并取得用户认可。

### 5.4 M0/M1：补分母、拆延迟，不借采样扩建产品

**M0 的最小产物。** 在同一会话的外部采样中记录时间戳、会话/epoch 标识、当前配置标识，以及现有 `/api/status` 的：

`translationAttempts`、`translationFailures`、`translationDeadlineExpired`、`sourceOnlyCues`、`translationDropped`。

状态接口还已有 `translationQueueDelayP50/P95`、`translationProviderDelayP50/P95`、`translationSuccessReadyLagP50/P95`、`translationBacklog`、`latencyWindowSamples`、`latencySampleAgeSeconds` 等指标，可直接记录，不增加产品计数器。

累计计数使用同会话、同配置的起止差值。延迟百分位按接口实际窗口及样本量比较，不对两个 P95 求差来冒充阶段耗时，也不将多个窗口 P95 直接平均。最基本的计数指标是：

`翻译失败 / attempt = ΔtranslationFailures / ΔtranslationAttempts`。

分母为零不计算。切会话、计数器重置、主动停止和仍在途任务要分开，不能把不同 cohort 拼成一个率。到期、dropped、source-only 单独列数值及各自口径，不假设它们互斥或都属于 attempts 的同一子集。有总 cue 数时才能报告“原文字幕占全部 cue 比例”。

**新会话的分母不能回填旧日志的七十五次失败。** 旧会话没有匹配起止分母就继续报告旧计数；新数据只说明新窗口。

帧路径只补 `requestVideoFrameCallback` 回调元数据 `mediaTime`、`presentedFrames`、`expectedDisplayTime`，以及 `document.hidden`、可见性/焦点变化、可可靠取得的遮挡状态，并保留 rAF、媒体进度和缓冲。遮挡取不到记 unknown，不能把失焦等同于遮挡；不改变 mute/visibility 来制造签名。rVFC 数据也不单独作为系统根因结案证据。

采样按有限窗口聚合，不能每帧同步落盘或无限累积；预先约定最大时长、费用和文件量。若采样造成负载或改变播放状态，立即撤掉采样，不保留为产品机制。

**M1 的决策输出。** 对超时窗口，使用现有阶段指标、原始日志和脱敏配置判断：期限主要已在排队时消耗，还是 provider 服务阶段占满，还是出现短预算兜底边界。对原因不清楚的项写明“没有足够阶段证据”，而不是把 provider 总耗时等同于连接握手成本。

- 若队列等待已吃掉可用期限，下一份方案针对现有队列/期限策略，而不是先复用 HTTP session。
- 若 provider 阶段主导，核对实际模型、请求配置与 cue 可用期限；任何换模型、调上下文、加并发或放宽字幕期限另作产品选择，不能自动执行。
- 只有连接建立成本被拆出且足以影响按期完成时，C2 才升级。
- B2 的正确性按边界用例独立验收；总体翻译收益按匹配窗口另验。单次成功、一次未卡或一次较低 p95 都不能替代可重复结果。

## 7. 这份计划什么时候应当作废

**不是“将来有新证据就继续观察”。出现以下证据时，要撤回受影响的排序或机制；若触及共同前提，则停止沿本计划实施，重新出决策单。**

### 7.1 使整份执行顺序失效的证据

1. **实际交接版本不再满足本计划的依赖关系。** 例如 A2 已被原作者修好，Stop 不再以这里描述的方式等待，或者新清理机制与 A1 的单一读者/共享生命周期假设冲突。此时当前排序不再作为执行授权；重新绑定代码基线，而不是按旧行号叠补丁。
2. **当前生产画像改变。** 当前不再用 Soniox、端点检测已关闭，或者真实数据证明 B1/C1 是持续卡顿的主要成本。此时“休眠/可达性未知所以暂缓”的理由被推翻，必须重排，不能仍以小清理排在前面。
3. **新的同会话、同配置、带分母与阶段的证据证明优先级基础相反。** 例如主要可避免损失出在队列淘汰/调度或连接建立，而不是本计划优先处理的预算边界；或者已有阶段归因不适用于当前模型配置。保留已完成的正确性修复，但撤回尚未实施的资源投入排序。
4. **全天连续使用成为当前立即必须通过的验收，或实际源即将跨 PTS 回绕。** R1 从独立后续门槛升为 A2 之后的核心正确性任务，不能继续先完成 A3/E1/C3/D1 来宣称本轮收工。
5. **无法保证单作者、还原点或安全停止。** 原作者仍写同一工作树、PID 不能确认、kill switch dry-run 失败时，实施和实验流程整体停止；不能以其他项目“文件空闲”绕开。

### 7.2 使特定机制或调查分支失效的证据

- **B2 策略失效：** 在可比短预算样本中，跳主损害按期有效译文产出或用户认可的质量，或者实际没有可尝试的兜底却仍跳主。回退策略并重新请用户选择，不能以“修了已确认 bug”抗拒结果。
- **A1 机制失效：** 有界读者仍让错误洪流堵 PCM，无法融入既有清理期限，或出现任务/进程残留、诊断反压。回退该补丁，再讨论其他机制；不能靠无限延长停止等待挽救方案。
- **C2 推进依据失效：** 等价对照显示复用没有可重复的端到端收益。撤销复用实施，不以连接数变少当作“性能优化成功”。
- **系统诊断分支失效：** 补齐可见性/遮挡后，rAF 空档被正常后台状态完整解释。撤销从这个样本追查显示调度故障的分支；这既不证明用户从未整机冻结，也不推翻 A1/A2。
- **E1 最小范围失效：** 统一分类必须改变用户可见的暂停、缓冲恢复或追赶语义，或者不是一个小接口调整可完成。停止把它当小一致性补丁，重新提交范围与行为选择。
- **任何边界回归：** 非回绕字幕对齐改变、恢复了 GPU 禁用、自动重连被接通、cue deadline 被延长、失败率或延迟出现可重复的恶化、出现残留进程等，立即撤回对应候选；涉及共同基线时暂停整批。

**作废的是本计划的选择、顺序或候选，不是自动否定已经独立确认的九条审计结论。** 一次没复现、一次测试通过或一段较低的失败计数，都不足以取消这些失效条件。
